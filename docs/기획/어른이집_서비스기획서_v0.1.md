# 어른이집 서비스 기획서

> 문서 버전: v0.1  
> 문서 상태: 초기 기획 초안  
> 작성일: 2026-08-21

## 1. 서비스 개요

### 서비스명

**어른이집**

### 한 줄 소개

보육교사가 직장 고민을 안전하게 나누고, 실무 자료와 이직 정보를 얻는 인증형 익명 커뮤니티.

### 핵심 메시지

**아이들을 돌보는 선생님도 돌봄이 필요하니까.**

## 2. 문제 정의

보육교사는 원장, 동료 교사, 학부모와 밀접하게 관계를 맺으며 일한다. 갈등이나 부당한 상황이 생겨도 업계가 좁고 신원이 노출될 우려가 있어 솔직하게 도움을 구하기 어렵다.

현장에서는 수업·놀이 준비와 관찰일지, 평가제, 가정통신문 등의 행정업무도 반복적으로 발생하지만 검증된 자료와 경험이 여러 카페, 블로그, 단체 대화방에 흩어져 있다.

이직을 고려할 때도 어린이집별 근무환경을 확인하기 어렵다. 공개된 정보만으로는 실제 분위기, 원장의 운영방식, 업무량과 휴게시간 준수 여부를 알기 힘들다.

## 3. 해결할 문제의 우선순위

1. **직장생활과 인간관계 고민**
   - 원장·동료·학부모와의 갈등
   - 부당한 업무지시와 근무조건
   - 번아웃, 퇴사 고민, 감정적 고립
2. **수업·놀이·행정업무 자료 공유**
   - 연령별 놀이와 수업 아이디어
   - 관찰일지, 알림장, 가정통신문 등 실무 작성 도움
   - 행사와 평가제 준비 경험
3. **이직 정보와 어린이집 후기**
   - 채용공고와 실제 근무조건 비교
   - 어린이집 근무 후기
   - 이직 준비, 면접 및 처우 협상 정보

## 4. 핵심 사용자

### 1차 사용자

현재 어린이집에서 근무하고 있으며 직장 문제를 주변에 드러내지 않고 상담받고 싶은 보육교사.

### 초기 핵심 페르소나

- **이름:** 김다정(가명), 28세
- **경력:** 민간 어린이집 보육교사 4년 차
- **상황:** 원장의 잦은 추가 업무와 학부모 응대로 지쳐 이직을 고민함
- **행동:** 검색, 맘카페, 블로그에서 정보를 찾지만 학부모 중심의 시선과 신뢰하기 어려운 정보에 피로를 느낌
- **필요:** 신원이 드러나지 않는 동료 상담, 현실적인 대응 방법, 믿을 수 있는 이직 정보

### 향후 확장 사용자

- 예비 보육교사와 휴직·퇴직 교사
- 유치원 교사 및 보육 관련 종사자
- 원장과 시설 관리자

초기에는 사용자 간 이해관계 충돌을 줄이기 위해 **현직·경력 보육교사 중심**으로 범위를 제한한다.

## 5. 서비스 가치 제안

| 사용자 상황 | 기존의 불편 | 어른이집의 가치 |
|---|---|---|
| 직장 갈등을 겪을 때 | 지인에게 말하면 신원이 퍼질 수 있음 | 교사 인증 기반의 익명 상담 |
| 급하게 자료가 필요할 때 | 자료가 여러 채널에 흩어져 있고 품질이 불분명함 | 현직 교사가 평가하고 정리한 실무 자료 |
| 이직을 준비할 때 | 공고만으로 실제 근무환경을 알기 어려움 | 검증된 경력자의 구조화된 근무 후기 |

## 6. 서비스 구조

### 6.1 속풀이방 — 1순위

직장생활과 관계 고민을 나누는 핵심 커뮤니티.

- 원장 때문에 힘들어요
- 동료 교사와의 관계
- 학부모 대응
- 퇴사·번아웃
- 급여·휴게시간·부당업무
- 오늘 있었던 일

게시글 작성 시 사용자가 원하는 반응을 선택하게 한다.

- 조언이 필요해요
- 비슷한 경험을 듣고 싶어요
- 해결책보다 위로가 필요해요
- 관련 제도나 법률 정보가 필요해요

### 6.2 교무실 — 2순위

수업·놀이·행정업무 노하우와 자료를 공유하는 공간.

- 연령과 주제별 놀이 아이디어
- 관찰일지·알림장 작성 도움
- 가정통신문과 행사 준비
- 평가제와 행정업무
- 교구·환경구성
- 자료 요청 및 공유

자료에는 대상 연령, 활동 시간, 준비물, 파일 형식 등의 메타정보를 붙여 검색성을 높인다.

### 6.3 이직반 — 3순위

어린이집 근무환경과 이직 경험을 확인하는 공간.

- 이직 상담
- 면접 후기
- 근무조건과 처우 정보
- 어린이집 후기
- 채용정보

어린이집 후기는 자유서술만 받지 않고 근무기간, 시설 유형, 업무량, 휴게시간, 급여 지급, 조직문화 등의 항목으로 구조화한다.

## 7. MVP 범위

1. 회원가입 및 교사 인증
2. 익명 프로필
3. 주제별 게시판
4. 게시글·댓글 작성
5. 공감, 도움됐어요, 저장
6. 신고·차단
7. 키워드 검색
8. 운영자 신고 검토 및 콘텐츠 관리

### 첫 버전에서 제외할 기능

- 사용자 간 개인 메시지
- 실시간 채팅
- 자료 유료 판매
- 복잡한 등급·포인트 제도
- 원장용 계정 및 기업 채용상품
- AI 상담과 문서 자동작성

개인 메시지는 괴롭힘, 신원 추적, 광고 위험 때문에 안전 체계가 갖춰진 뒤 검토한다.

## 8. 핵심 사용자 흐름

1. 서비스 방문
2. 커뮤니티 일부 콘텐츠 열람
3. 가입 및 교사 인증
4. 자동 생성된 익명 프로필로 고민 작성
5. 비슷한 경험을 가진 교사의 댓글과 공감 수신
6. 도움된 답변 저장 또는 후속 상황 공유
7. 필요할 때 실무 자료와 이직 정보 탐색

## 9. 차별점

- **직군 특화:** 일반 직장인 커뮤니티가 다루지 못하는 보육 현장의 맥락을 반영한다.
- **인증된 익명성:** 신원은 운영 체계에서 확인하되 커뮤니티에서는 공개하지 않는다.
- **감정과 실무의 연결:** 위로만 제공하거나 자료만 모으는 것이 아니라 고민 해결에서 실무·이직 정보까지 이어진다.
- **구조화된 후기:** 명예훼손성 폭로 게시판이 아니라 근무조건을 비교할 수 있는 데이터로 축적한다.

## 10. 운영 및 안전 원칙

- 아동, 학부모, 교사 개인을 특정할 수 있는 이름·사진·연락처 게시 금지
- 어린이집 후기 작성 시 재직 중임을 추정할 수 있는 상세정보 노출 경고
- 사실 주장과 개인적 의견을 구분해 작성하도록 안내
- 욕설, 혐오, 따돌림, 신상 추적, 허위사실, 광고를 신고 대상으로 지정
- 아동학대 의심이나 자해 위험 등 긴급 사안은 전문 신고·상담기관으로 연결
- 인증 원본은 최소한으로 수집하고 인증 처리 후 보관 범위를 제한

어린이집 실명 후기 기능은 개인정보, 명예훼손, 허위 후기 대응정책을 마련한 뒤 단계적으로 출시한다.

## 13. 초기 수익모델 가설

커뮤니티 신뢰를 먼저 확보한 뒤 수익화를 도입한다.

- 검증된 프리미엄 실무자료 구독
- 보육교사 교육·자격 과정 제휴
- 이직·채용 매칭 수수료
- 교사 복지상품과 업무도구 제휴
- 어린이집 대상 채용공고 상품

사용자 고민글이나 민감한 이직 데이터를 광고 타기팅에 활용하지 않는 것을 원칙으로 한다.

## 14. 현재 결정된 사항

- 핵심 타깃은 보육교사이다.
- 서비스 형태는 인증 기반 익명 커뮤니티이다.
- 기능 우선순위는 `직장생활·인간관계 → 실무자료 → 이직정보·어린이집 후기`이다.
- 첫 번째 MVP는 직장 고민을 안전하게 묻고 답하는 경험에 집중한다.

## 15. 추가로 결정할 사항

1. 가입 대상: 현직 교사만 허용할지, 자격증 보유자와 퇴직 교사도 포함할지
2. 인증 방식: 자격증, 재직증명, 보육교직원 통합정보 등 어떤 방법을 사용할지
3. 공개 범위: 비회원에게 게시글을 어느 정도까지 공개할지
4. 익명 방식: 고정 닉네임, 글마다 다른 닉네임, 경력만 공개 중 무엇을 택할지
5. 어린이집 후기: 실명 시설 단위로 제공할지, 초기에는 유형·지역 단위로 제한할지
6. 초기 플랫폼: 모바일 웹, 앱 또는 카카오톡 기반 검증 중 무엇부터 시작할지

## 16. 기술 스택

### 기술 방향

초기에는 **검색 가능한 반응형 웹**으로 사용자를 확보하고 커뮤니티를 검증한다. 웹은 Next.js, 백엔드는 Supabase를 사용한다. 앱 설치가 실제 성장에 필요하다는 지표가 확인되기 전까지 별도 모바일 앱은 만들지 않는다.

### 확정 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| 웹 | Next.js · React · TypeScript | 검색 노출, 서버 렌더링, 반응형 웹 제공 |
| UI | HTML · CSS | 접근성과 검색 노출에 유리하며 초기 UI 의존성 최소화 |
| 모바일 초기 대응 | 반응형 웹 · PWA | 앱 설치 없이 모바일에서 사용하고 홈 화면 추가 지원 |
| 백엔드 | Supabase | 인증, 데이터베이스, 파일 저장소를 한 서비스에서 제공 |
| 데이터베이스 | PostgreSQL | 게시글, 댓글, 사용자, 신고처럼 관계가 명확한 커뮤니티 데이터에 적합 |
| 접근 제어 | Supabase Auth + RLS | 인증 상태와 교사 인증 등급에 따라 행 단위 권한 적용 |
| 파일 저장 | Supabase Storage | 교사 인증서류와 수업자료 저장, 버킷별 접근 정책 적용 |
| 웹 배포 | Vercel | Next.js 기능과 배포 흐름을 별도 설정 없이 지원 |
| 향후 앱 | Expo · React Native | 앱 필요성이 검증되면 React 생태계를 활용해 Android·iOS 개발 |
| 버전 관리 | GitHub | 코드 리뷰, 이슈 관리, 자동 배포의 기준 저장소 |
| 테스트 | Node.js 기본 테스트 또는 필요한 최소 도구 | 복잡한 테스트 프레임워크를 미리 도입하지 않음 |

### 초기 웹 구조

기능 단위로만 폴더를 나누고 별도의 복잡한 계층은 만들지 않는다.

```text
src/
├── app/          # 페이지와 서버 기능
├── components/   # 두 곳 이상에서 쓰는 UI
└── lib/          # Supabase 연결 등 공통 코드
```

기능별 폴더와 별도 상태관리 계층은 실제 파일이 늘어날 때 추가한다.

### 플랫폼 출시 순서

1. 검색 가능한 반응형 웹으로 핵심 흐름 검증
2. PWA로 홈 화면 추가와 기본 앱 경험 제공
3. 재방문과 알림 지표가 앱 개발 비용을 정당화할 때 Expo 기반 앱 출시

고민글은 작성자가 공개 범위를 선택하게 하고, 공개로 설정된 글만 검색엔진에 노출한다. 인증정보, 개인식별정보와 민감한 상담글은 검색 대상에서 제외한다.

### 보안 원칙

- 모든 공개 스키마 테이블에 RLS를 활성화하고 필요한 권한만 허용한다.
- 교사 인증 여부는 사용자가 수정할 수 없는 서버 측 데이터로 관리한다.
- Supabase의 공개용 키만 브라우저에 노출하고 `service_role` 키는 서버 환경변수로만 관리한다.
- 인증서류는 일반 자료와 버킷을 분리하고 운영자만 열람할 수 있게 한다.
- 인증 완료 후 원본 서류의 삭제 시점과 보관 근거를 운영정책에 명시한다.
- 아동과 교직원의 개인정보가 포함된 자료 업로드를 금지하고 신고·삭제 절차를 제공한다.

### 지금 도입하지 않는 기술

- 별도 Node.js·Spring 백엔드 서버
- 초기 네이티브 모바일 앱
- 마이크로서비스와 Kubernetes
- GraphQL 서버
- Redis, Elasticsearch, 메시지 큐
- 별도의 관리자 앱
- Redux 등 별도 전역 상태관리
- UI 컴포넌트 프레임워크

서비스 규모나 기능 요구가 실제로 확인되기 전까지는 Supabase와 PostgreSQL의 기본 기능으로 운영한다.

### 재검토 조건

- 검색 품질이 PostgreSQL 전문 검색으로 부족할 때 검색엔진 도입
- 댓글 알림과 재방문 지표가 충분할 때 Expo 앱과 푸시 알림 도입
- 관리자 비밀키가 필요한 업무가 늘어날 때 Supabase Edge Functions 추가
- 데이터 규모, 비용 또는 국내 개인정보 보관 요건이 현재 호스팅 방식과 맞지 않을 때 백엔드 이전 검토
